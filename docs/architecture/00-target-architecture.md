# 新アプリの設計

## 目的

後任者がバックアップ項目を安全に追加でき、利用者がバックアップと復元を取り違えず、Windows 7～11の32/64ビットPC間でデータを移せるアプリを作る。

## 起動と画面

起動直後は実作業を選ぶ3モード画面とし、実行画面内でバックアップ/復元を切り替えない。

```text
モード選択
├─ データバックアップ
│  ├─ 通常ファイル
│  ├─ ブラウザーブックマーク
│  ├─ 会計ソフトデータ
│  └─ Wi-Fi設定の暗号化バックアップ
├─ Wi-Fi設定の復元
└─ ブラウザーブックマークの復元
```

各専用画面は「モード選択へ戻る」を持つ。起動画面には検出したOSビット数とプロセスビット数を表示する。

## プロジェクト境界

```text
Ytec.WindowsBackup.App
  ├─ WPF画面、確認、進捗
  └─ 1インスタンス制御

Ytec.WindowsBackup.Windows
  ├─ netsh Wi-Fi取得/登録
  ├─ アプリ内蔵鍵
  ├─ Chrome/Edge安全復元、Firefox復元案内
  ├─ SSD/HDD特性判定
  └─ 新規出力物に限定したEveryone所有者・ACL設定

Ytec.WindowsBackup.Core
  ├─ Catalog: JSON読込とスキーマ検証
  ├─ Planner: 読み取り専用スキャンとコピー計画
  ├─ Executor: 並列・非上書きコピー
  ├─ Supplement: Wi-Fi等の追加バックアップ境界
  └─ Manifest: 結果と失敗の版付き記録
```

ターゲットは `.NET Framework 4.6.1`、通常配布は `AnyCPU` とする。バックアップ形式にプロセス固有のポインター長やネイティブ構造体を保存しない。

## コピー

- SSD→SSDはCPU数に応じて最大12並列、小/中ファイルを中心に同時コピーする。
- 64MiB以上の大容量ファイルは別の並列上限を設ける。
- HDDを検出した場合は2並列・大容量1並列へ落としてシーク競合を抑える。
- USB外付けSSDもWindowsが「シークペナルティなし」と報告すればSSD方式を使う。
- 判定不能時は4並列・大容量2並列。
- 1MiBバッファ、非同期・順次読み取り、一時名 `CreateNew`、完了後の名前確定を使う。
- 通常コピーが共有違反またはアクセス拒否になったファイルだけ、同一ボリュームのVSSスナップショットから再取得する。
- VSSスナップショットは必要なボリュームごとに遅延作成し、ジョブ終了時に成功・失敗を問わず削除する。

ストレージ性能を自動判定できない機器では安全な標準値へ戻す。実測ベンチマークによる自動再調整は今後の候補とする。

## 安全設計

- 計画と実行を分け、計画完了前は開始できない。
- 元ドライブ配下を保存先に指定できない。
- 宛先は毎回一意な新規ジョブフォルダー。
- ファイルは一時名へ `CreateNew` で書き、完了後だけ正式名へ移動。
- 再解析ポイントを追跡しない。
- 元データのACL、所有者、属性、内容を変更しない。
- OneDrive / iCloud等のオンライン専用・一部未取得ファイルは開かずに除外し、PC内に完全な実体があるファイルだけをコピーする。
- オンライン専用除外は計画時とコピー直前に判定し、除外件数と論理サイズを画面・マニフェストへ記録する。アプリからクラウドファイルを自動取得しない。
- コピー先の既存ファイルを上書きしない。
- マニフェストには元ドライブの絶対パスを保存しない。
- キャンセルされた一時ファイルだけを削除し、完了済みデータは残す。
- バックアップ先がFAT32と判定できた場合、4GB超ファイル等の制約を安全に扱えないため実行を許可しない。
- exFATはコピーを許可するが、所有者・ACLを保存できないため事前警告し、ACL処理を行わず理由をマニフェストへ記録する。
- NTFSまたはReFSではコピー完了後だけ、今回作成したジョブフォルダー配下の所有者を `Everyone`、DACLを継承可能なフルアクセスへ変更する。
- ACL処理前にジョブフォルダーが保存先直下かを再検証し、対象外パスを拒否する。
- ACL変更件数と失敗件数をマニフェストへ保存する。

## 項目設定

`config/backup-items.v1.json` は表示とコピー元候補だけを定義する。任意コード実行機能は持たない。

- `schemaVersion`: 現在は1のみ
- `id`: 小文字英数とハイフンの固定ID
- `kind`: `FileCopy` または登録済みOS追加処理
- `scope`: `PerUser` または `SourceRoot`
- `selectionMode`: `AllFiles` / `FilesOnly` / `ExtensionsOnly`
- `paths`: 安全な相対パス。各階層で `*` / `?` を許可
- `extensions`: 拡張子検索時の許可一覧

`**`、未知の版、重複ID、絶対パス、親参照、不正文字を起動時に拒否する。ワイルドカード展開時も再解析ポイントを除外する。

## Wi-Fiバックアップ

1. 現在実行中のPCから `netsh` で一時XMLを取得
2. XMLサイズ、名前空間、ルート、プロファイル名を検証
3. アーキテクチャ非依存の独自コンテナへ暗号化
4. ジョブ内の `windows-settings/wifi/wifi-profiles.ywbwifi` へ保存
5. 平文一時フォルダーを削除
6. 通常データとまとめてジョブ全体へEveryone ACLを適用

復元はコンテナの改ざん検知、XML再検証、ランダム一時名、`netsh wlan add profile` の順で行う。SSIDや鍵を画面・マニフェスト・コマンド出力ログへ記録しない。

## ブックマーク復元

- Chrome / Edge:
  - 同一ブラウザーの現在プロファイルだけを復元先にする。
  - ブラウザープロセスが動作中なら拒否する。
  - 復元元JSONに`roots`オブジェクトがあることを検証する。
  - 現在の`Bookmarks`と`Bookmarks.bak`をユーザー専用領域へ退避する。
  - 一時ファイルを再検証後、`File.Replace`または`File.Move`で確定する。
- Firefox:
  - `.json`または`mozLz40\0`ヘッダー付き`.jsonlz4`を検証する。
  - `places.sqlite`を直接上書きしない。
  - Firefox公式の「インポートとバックアップ → 復元 → ファイルを選択」手順を案内する。
