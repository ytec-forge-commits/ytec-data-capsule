# Wi-Fi暗号化の安全境界

更新日: 2026-07-27

## 目的

別PC移行をパスワード入力なしで行いながら、バックアップ先にSSID・Wi-Fiキーの平文XMLを残さない。

## コンテナ

- マジック: `YTECWIFI`
- 形式版: 2
- アプリ鍵ID: 1
- ランダムソルト: 16バイト
- ランダムIV: 16バイト
- 暗号化: AES-256-CBC / PKCS#7
- 改ざん検知: HMAC-SHA-256
- 構成: Encrypt-then-MAC
- 暗号鍵と認証鍵は、マスター鍵、用途バイト、ラベル、ソルトから個別に導出
- HMAC検証に成功するまで復号しない

暗号化内容はJSONだが、コンテナ外からはSSID、Wi-Fiキー、XMLを読めない。

## 鍵

マスター鍵はアプリに埋め込まれた素材から生成する。ユーザー入力、PC固有DPAPI、外部サーバーを使わないため、32/64ビットやPCをまたいで復元できる。

この方式は、紛失したバックアップ媒体から平文を容易に読むことを防ぐためのもの。EXE、メモリ、ソースを詳しく解析できる相手には鍵を再現され得る。強い解析耐性、利用者ごとの秘密分離、失効、鍵ローテーションは提供しない。

## 平文一時領域

`netsh wlan export profile key=clear` はWindows仕様上、一時的に平文XMLを作る。

対策:

1. `%LOCALAPPDATA%\Y-TEC\WindowsBackup\wifi-temp\<GUID>`だけを使用
2. GUID直下以外を削除対象にしない
3. 再解析ポイントを拒否
4. 現在ユーザー、SYSTEM、Administratorsだけにフルアクセスを付与
5. XMLのサイズ、WLANProfile名前空間、プロファイル名を検証
6. 暗号化後、正常/失敗/キャンセルの`finally`で削除
7. アプリを1インスタンスに限定
8. 次回起動時、同じ一時ルート直下のGUIDフォルダーだけを回収

SSDでは「安全な上書き消去」を保証できないため、上書き回数による安全消去はうたわない。異常終了から次回起動までの間は一時XMLが残る可能性がある。

## ログと表示

- `netsh`標準出力・標準エラーを取得しない
- SSID、Wi-Fiキー、XMLファイル名を画面やマニフェストへ記録しない
- 復元エラーはプロファイル番号と終了結果だけを記録
- 一時ファイル名は`profile-0001.xml`形式とし、SSIDを使わない

## 出力ACLとの関係

暗号化済み`.ywbwifi`はバックアップジョブの一部なので、NTFSまたはReFSでは最終的にジョブ全体と同じ`Everyone`所有者・フルアクセスACLになる。exFATではファイルシステムが所有者・ACLを保存しないため適用対象外となる。平文一時XMLにEveryone ACLは付けない。

## 制限

- Wi-Fi接続中のパケットやWindows資格情報保護機構を保護する機能ではない
- Windows側または無線LANアダプターが受け付けないプロファイルは復元できない
- 新OS固有の認証方式を旧OSが理解できない場合はプロファイル単位で失敗する
- 企業802.1X証明書、外部証明書、ハードウェア鍵の移行成功は保証しない
